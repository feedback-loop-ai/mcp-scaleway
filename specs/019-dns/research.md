# Research: Scaleway Domains and DNS MCP Tools

**Feature**: 019-dns | **Date**: 2026-03-11

## Technology Decisions

### Scaleway SDK Client Pattern

The project uses `@scaleway/sdk-client` with `createClient()`. The DNS API is accessed via the Scaleway REST API through the SDK client. The SDK client handles authentication and base URL routing.

API calls follow the pattern:
```typescript
const client = createScalewayClient(config);
const response = await client.fetch<T>({ method, path, body, urlParams });
```

### DNS API Structure

The Scaleway Domains and DNS API is **global** (not zoned or regional). Base URL pattern:
```
https://api.scaleway.com/domain/v2beta1/
```

This is different from most other Scaleway APIs (e.g. Instances, which are zone-scoped). No zone or region parameter is required for any DNS operation.

Key API groups:
- **DNS Zones**: `/dns-zones` - CRUD plus clone and refresh operations
- **DNS Records**: `/dns-zones/{dns_zone}/records` - List, batch update, and clear
- **Raw Zone**: `/dns-zones/{dns_zone}/raw` - Export/import BIND zone files
- **Nameservers**: `/dns-zones/{dns_zone}/nameservers` - List and update
- **SSL Certificates**: `/ssl-certificates` - CRUD operations
- **TSIG Keys**: `/dns-zones/{dns_zone}/tsig-key` - Get and delete

### DNS Zone Name as Identifier

Unlike other Scaleway resources that use UUIDs, DNS zones are identified by their full name (e.g. `sub.example.com`). This name is used directly in URL paths and must be URL-encoded via `encodeURIComponent()`.

### Batch Record Updates

The DNS API supports a powerful batch update mechanism via `PATCH /dns-zones/{dns_zone}/records`. The request body contains a `changes` array where each element is one of:
- **add**: Append new records
- **set**: Replace records matching a name+type combination
- **delete**: Remove a specific record by ID or by name+type
- **clear**: Remove all records

This is modeled as a Zod discriminated union (`RecordChange`) in the type definitions.

### Record Types

The API supports 21 DNS record types: A, AAAA, CNAME, TXT, SRV, TLSA, MX, NS, PTR, CAA, ALIAS, LOC, SSHFP, HINFO, RP, URI, DS, NAPTR, DNAME, HTTPS, SVCB.

### Error Handling

All Scaleway API errors come back as Error objects with a `statusCode` property. The shared `mapScalewayError` function in `src/shared/errors.ts` handles the mapping to MCP error types. Each handler wraps its logic in a try/catch that calls `formatErrorResponse(mapScalewayError(error))`.

### Pagination

List endpoints (zones and records) use the shared pagination pattern with `page` (1-indexed) and `page_size` query parameters. Responses include `total_count`. The shared `paginationToQuery()` and `buildPaginatedResponse()` utilities are used.

Nameserver listing does not use pagination (returns all nameservers for a zone).

### Raw Zone Format

The raw zone export/import uses BIND zone file format. Export returns the zone content as text, while import accepts BIND-formatted content wrapped in a `bind_source.content` field.

### SSL Certificates

The SSL certificate endpoints are under `/ssl-certificates` rather than under `/dns-zones`. The `dns_zone` name serves as both the certificate identifier and the primary subject. Alternative DNS zones can be specified as Subject Alternative Names (SANs).

### TSIG Keys

TSIG (Transaction Signature) keys are used for authenticated DNS zone transfers. The API only supports get and delete operations (keys are auto-generated by Scaleway).
